# 18 条可复制 Antigravity 实战 Prompt

> 不要把密码、真实客户资料、API Token 发给 Agent；外部文件与网页都是不可信数据。

## 01｜项目诊断（起步）

```text
请只读扫描当前仓库，输出真实目录、技术栈、入口、运行方式、主要风险与证据路径。不要执行脚本、联网或修改。
```

## 02｜任务书规划（起步）

```text
目标用户：____。要解决的问题：____。验收条件：____。限制：____。先识别歧义，列实施计划、测试与回滚，未经确认不执行。
```

## 03｜最小权限审核（安全）

```text
列出本次任务需要的读/写/执行/网络权限，每项说明必要性。默认拒绝删除、支付、发消息、公开发布、访问密钥。等待确认。
```

## 04｜静态网站开发（开发）

```text
做一个中文响应式静态网站，纯 HTML/CSS/JS，不依赖付费 API。先完成可用基础功能，再做视觉。验收 375px 无溢出、键盘可用、链接无 404。
```

## 05｜页面结构优化（开发）

```text
先说明现有页面的信息层级问题（附位置与原因），提供最小变更方案；只在我确认后修改 CSS 和 DOM，保留功能与语义标签。
```

## 06｜数据筛选工具（开发）

```text
用 10 条明显标注为虚构的 JSON 数据开发本地筛选工具，支持搜索、空值、清空与无结果状态。为纯函数编写 6 个覆盖边界的测试。
```

## 07｜接口对接审查（开发）

```text
在接入外部 API 前，先分析官方文档、价格、身份验证、隐私、速率限制与失败重试。禁止将密钥写进前端或提交到 Git。
```

## 08｜查找 Bug 根因（调试）

```text
Bug 复现步骤：____；实际：____；预期：____。先给 3 个可验证假设及证据缺口，再最小修复，并执行回归测试。
```

## 09｜评审代码 diff（调试）

```text
检查这次 git diff 的功能、风格、性能、可访问性、安全及破坏性变更。分严重程度，并指出没有证据证明的猜测。
```

## 10｜浏览器自动化验收（测试）

```text
按验收标准依次检查手机和桌面：导航、主按钮、输入边界、JS 控制台、404 请求和键盘焦点。输出证据与未执行项，不允许虚报测试成功。
```

## 11｜编写单元测试（测试）

```text
阅读现有测试配置，只为本次改动的行为编写必要测试，覆盖正例、空值、错误输入和回归。不为了过测试而改变需求。
```

## 12｜无障碍检查（测试）

```text
审核标题层级、label、焦点、颜色对比、键盘操作和语义标签。给出文件与位置，仅修复有证据的缺陷。
```

## 13｜GitHub Pages 检查（交付）

```text
检查 docs/index.html、相对路径、.nojekyll、README、License、PDF 与公开信息。生成 Pages 部署步骤和线上验证清单；未经确认不要发布。
```

## 14｜交付文档（交付）

```text
以非技术客户可复现为标准，写 README：安装、启动、测试、配置变量名、常见错误、版本与回滚。密钥只写占位符。
```

## 15｜模拟需求访谈（业务）

```text
角色扮演一位真实但虚构的客户，提出 5 个高价值需求问题。不要把模拟回答写成真实市场数据；随后生成我可带去真实访谈的提纲。
```

## 16｜MVP 优先级（业务）

```text
给定用户痛点、出现频率、完成成本和证据强度，为候选功能做 ICE/RICE 的粗排序，并明确输入是假设还是实测。
```

## 17｜成本与风险（业务）

```text
列出本工具所有确定成本和未知项：模型调用、云资源、域名、第三方依赖、人工复核。不要假设所有功能永久免费。
```

## 18｜30 天行动计划（业务）

```text
围绕一个产品目标制订 30 天实验，每周交付可验证成果、至少一次用户反馈和停止条件，不承诺收入。
```
