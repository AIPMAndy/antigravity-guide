# 07｜Bug 修复：给证据而不是猜原因

> 工程 · 35 分钟 · 交付物：一条有复现、测试、修复 diff 的问题记录

## 这章解决什么问题

高效调试是建立最小复现和反证，不是对 Agent 说“还是不行”。

## 按顺序动手

### 1. 写清复现步骤

版本、操作系统、URL、输入、期望、实际表现。涉及隐私的日志先脱敏。

### 2. 收集证据

截图、控制台错误、网络失败记录。浏览器工具可协助检查，但必须核验它是否真正访问了页面。

### 3. 要求最小修复

先提出根因假设和验证办法，尽量只改目标文件，禁止改与故障无关的 UI。

### 4. 做回归测试

先证实原 Bug 消失，再测三条关联路径。提交前检查 diff。

## 复制给 Antigravity 的任务指令

```text
请处理 Bug：步骤 ____；预期 ____；实际 ____；错误信息（已脱敏）____。先给出 2–3 个可验证的根因假设与证据缺口，只修改与根因直接相关的代码。修复后输出最小 diff、复现验证和 3 条回归测试；如果无法复现，明确说没有复现。
```

## 验收标准
- [ ] 修复前能复现
- [ ] 修复后有客观测试结果
- [ ] 改动范围受控且可回滚

## 避坑提醒
- 不接受“应该好了”式结论
- 切勿把 token、Cookie 贴入聊天或 Issue
- 不让 Agent 为修一个按钮而全站换框架
