# 05｜项目一：60 分钟做可用的落地页

> 实战 · 60–90 分钟 · 交付物：一个可本地打开、手机适配的落地页

## 这章解决什么问题

先做一个不接真实支付、不采集敏感信息的 MVP。目标是验证页面效果与交付流程，而不是堆功能。

## 按顺序动手

### 1. 选题：AI 简历改写示范页

定义目标人群、主张、3 个可信能力点、FAQ 与一个跳转联系链接；示例案例显著标注“虚构演示”。

### 2. 要求无依赖静态实现

生成 index.html、style.css、script.js，中文响应式，强调语义标签、键盘可用与 375px 屏幕。

### 3. 本地预览

使用 python3 -m http.server 8000，逐项点击导航与按钮；不接受仅展示静态截图。

### 4. 修一个关键问题

让 Agent 根据真实复现步骤修复，例如手机文字溢出或按钮无反馈，禁止顺便重写其他模块。

### 5. 交付验收包

截图桌面/手机各一张、README、文件树、测试记录。

## 复制给 Antigravity 的任务指令

```text
在当前空目录创建“AI 简历诊断演示”中文静态落地页：目标用户是求职新人；页面包含 Hero、适用人群、工作流程、FAQ、联系 CTA。用虚构案例，不编造客户评价或转化数据。不接支付、不采集个人信息、无外部依赖。交付 index.html、style.css、script.js、README。验收：375px 无横向滚动，导航有效，键盘能操作，控制台无错误。先给计划，再逐步实现并自测。
```

## 验收标准
- [ ] 真实文件可离线打开
- [ ] 手机布局无溢出，按钮有实际动作
- [ ] 案例、来源与费用说明没有虚构为真实

## 避坑提醒
- 能截图不代表能运行
- 演示表单不要伪装成已发送真实请求
- 技术效果与获客转化是两个不同指标
