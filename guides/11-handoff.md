# 11｜客户交付与团队协作 SOP

> 交付 · 35 分钟 · 交付物：README、交付清单和维护协议

## 这章解决什么问题

客户买的是可用结果，不是 AI 生成的代码。项目必须可接管、能维护且有责任边界。

## 按顺序动手

### 1. 明确交付边界

写清页面数、支持设备、数据来源、包含与不包含、账号归属、验收窗口。

### 2. 建立接管文档

README 包含启动命令、目录解释、如何更新、如何回滚、环境变量名称、不包含真实密码。

### 3. 明确资产和授权

字体、图片、代码依赖、商标、客户素材分别确认授权，避免默认“AI 做的都可商用”。

### 4. 安排人工验收

由业务负责人检查文案、价格、合规声明和真实链接；技术负责人核实运行与安全。

### 5. 交付后留维护窗口

约定 bug 响应、内容更新方式、版本记录和费用，不做无边界承诺。

## 复制给 Antigravity 的任务指令

```text
请基于当前仓库输出一份给非技术客户的交付说明：交付内容、功能清单、启动与更新、验收步骤、限制、第三方依赖与费用、故障回滚、后续维护边界。凡没有实际测试证据的内容标“待验证”，不要编造性能或客户评价。
```

## 验收标准
- [ ] 非技术人员可按 README 开启项目
- [ ] 付款、上线与维护责任边界清晰
- [ ] 依赖和素材授权有记录

## 避坑提醒
- 上线之后才发现客户没有管理员权限
- 未经授权复用第三方素材
- 没有验收标准就承诺无限修改
